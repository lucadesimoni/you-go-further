# Languages

English and German, with German written for **Switzerland**.

## How it works

`src/i18n/` holds two plain dictionaries and a small provider — no i18n
framework, because two languages and flat keys don't need one.

```
en.ts   the source language, and the shape every locale must match
de.ts   typed as `Dictionary`, so a missing key is a compile error
index.tsx  <I18nProvider>, useT(), translate()
```

* **Keys, not English strings**, are what components reference, so a wording
  change happens in one place.
* **Placeholders** are `{name}`: `t("account.streak", { days: 5 })`.
* **Plurals**: a key with a `_one` sibling uses it when `count` is exactly 1.
  That covers both languages without pulling in ICU message formatting.
* **Fallback** is English — a missing string shows real text, never a raw key.

## Swiss German conventions

* **ss, never ß.** Switzerland dropped the Eszett: *Strasse*, *Grösse*,
  *gemässigt*. A test fails the build if a `ß` appears.
* **Sie throughout.** Swiss sports brands address customers formally.

## Choosing a language

Detected from the browser (`de-*` → German), overridable in the account menu,
and on the **sign-in screen** as well — otherwise a German speaker on an
English-language browser has no way to switch before signing in. The choice is
stored in `localStorage` and sets `<html lang>`, which screen readers use to
pick pronunciation.

## What the guard tests enforce

`src/i18n/i18n.test.ts` fails on: a missing German key, a German key English
doesn't have, an accidentally-identical string (with an explicit allow-list for
words like *Triathlon* and *Pause* that really are the same), mismatched
placeholders, a `ß`, a stray non-Latin character, and an empty value.

It also fails on a **dead key** — one no component references. A dictionary
should describe what the app actually says; an unused key is dead weight a
translator would waste effort on, and it hides the fact that a screen was never
wired up. That check found 44 such keys the first time it ran, which is exactly
the mistake it exists to catch. Keys built at the call site
(`` t(`appearance.${choice}`) ``) are matched by prefix rather than literally.

## Coverage — what is and isn't translated

**Translated:** the whole app shell and navigation, the account menu, sign-in and
the magic-link flow, the planner (including every goal, activity, intensity and
conditions option), insights and the fuelling score, profile and health, the
connect/route panel headings, catalog and cart headings, and the user-facing
toasts.

**Still English**, and deliberately so for now:

| Area | Why |
| --- | --- |
| The 16 nutrition-guide articles | Several thousand words of clinical prose. Translating it is a content and review task, not a code one — a machine translation of dosing guidance is not something to ship. The UI around them is translated and says the articles are English. |
| Admin, Team and platform-settings screens | Staff-facing, used by the operator rather than the athlete. |
| Engine-generated rationale strings | The recommendation "why" lines are produced in `src/engine/`. Moving them to keys is a mechanical follow-up; they are currently English in both languages. |
